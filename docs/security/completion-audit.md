# تطبیق تحویل با متن هدف

مرجع: متن پیوست مالک؛ دامنه و میزبان نهایی با پاسخ مستقیم «فعلا مشخص نیست» نامعلوم‌اند. معیار این تحویل، اصلاح و اثبات محلی و آماده‌سازی فعال‌سازی است؛ انتخاب/اجرای میزبان، انتشار و migration عملیاتی درخواست نشده‌اند.

| بند هدف | شواهد کد و نتیجهٔ لازم | وضعیت تحویل |
|---|---|---|
| ۱ ـ دستورالعمل پروژه، نصب و خواندن اسکیل‌های پنج‌گانه، React/TS/Express | `skills.md`؛ سه اسکیل جدید از منابع اصلی، دو اسکیل موجود؛ منابع framework/auth/SQL خوانده شدند. اسکن‌ها جدا در verification ثبت‌اند. | انجام‌شده |
| ۲ ـ حفظ کار، بررسی کد فعال/مهاجرت/تست/استقرار/وابستگی و مدل تهدید | پوشه Git ندارد؛ snapshot و manifest در `.local/security-baseline-20261027`. تغییرات امنیتی روی کد فعال انجام شده‌اند. `varsassafra-threat-model.md` و `findings.md` شناسه، شدت، شرط، اثر، کنترل، شواهد و وضعیت را جدا می‌کنند. | انجام‌شده؛ تاریخچهٔ Git قابل بررسی نبود |
| ۳ ـ حساب مدیر، Argon2id، نشست hash و cookie، خروج/idle/absolute/revoke | `lib/admin-security.ts`، `0010_security.sql`، `AdminLogin.tsx`، `AdminSecurity.tsx`، `orders-api.ts`؛ تست auth و مرورگر. Bearer قدیمی رد می‌شود و credential در web storage ذخیره نمی‌شود. | اجرا و تست‌شده |
| ۳ ـ TOTP معتبر، تأیید ثبت، secret رمزگذاری‌شده، recovery hash یک‌بارمصرف، reauth | OTPAuth + AES-GCM؛ counter و recovery در transaction؛ enrollment مجوز پنل ندارد؛ تست replay/concurrency/removal/change-password و cookie امن production. | اجرا و تست‌شده |
| ۳ ـ bootstrap/انتقال و بازیابی، بدون ساخت عمومی و bypass production | CLI ساخته‌شده `dist/admin-account.mjs`، `operator-verification.json`، راهنمای deployment؛ reset نشست، عامل‌های قبلی و رمز را تغییر داد. unitها NODE_ENV را روی خود process تثبیت می‌کنند. | مسیر محلی آزموده و راهنمای عملیاتی آماده |
| ۴ ـ OTP، مالکیت سفارش/آدرس/تیکت/فایل، عدم تعویض نشست‌ها | `modules/customers` و `modules/files`؛ نشست‌های جدا؛ شناسه از سرور؛ تست دو مشتری، forged IDs، claim مهمان و فایل خصوصی. OTP دارای TTL، تلاش محدود، مصرف اتمیک و resend پایدار است. | اجرا و تست‌شده |
| ۴ ـ تغییر شماره و بازیابی | `auth.changePhone` به نشست و OTP هر دو شماره نیاز دارد، merge خودکار نمی‌کند و نشست‌ها را باطل می‌کند. بازیابی بدون شماره فقط با احراز انسانی مالک، در deployment مستند است. | API تست‌شده؛ فرم جدید تغییر شماره جزو تغییرات UI نیست |
| ۵ ـ Helmet/CSP/CORS/CSRF و نبود Origin، GET، cookie/proxy/errors/حدود درخواست | middlewareهای `http-security` و `app`، `beforeApiBody`، parser محدود و بدون inflate، timeoutهای Node/Nginx، URLهای allowlist. HTML metadata در پاسخ‌دهندهٔ واقعی preview header می‌گیرد؛ ۱۵ probe و browser زیر CSP اجرا شدند. GET کسب‌وکار ایجاد/ویرایش نمی‌کند؛ touch نشست و صدور nonce امنیتی از جنس عملیات سفارش نیست. | محلی اجرا و تست‌شده |
| ۵ ـ TLS در لایهٔ پاسخ، پرهیز از HSTS بدون دامنه | فایل‌های Nginx برای server HTTPS میزبان آماده‌اند؛ HSTS خاموش است. به‌علت نبود دامنه/میزبان، TLS عملیاتی ادعا نشده است. | نیازمند تنظیم میزبان، صریحاً مستند |
| ۶ ـ محدودسازی پایدار چندنمونه‌ای، نه صرفاً IP | PostgreSQL upsert/row lock برای account/phone/network/global؛ admin/MFA، OTP request/verify، checkout، contact، support و upload. آزمایش دو API واقعی، target rotation و forwarded headers. | اجرا و تست‌شده |
| ۶ ـ سقف پیامک، مصرف و هشدار، حفظ قیمت/idempotency/رزرو | بودجهٔ مشترک `reserveSms` برای API و worker؛ سقف ساعت/روز و audit/هشدار ثابت با تست exhaustion. قیمت و inventory در تراکنش اصلی باقی مانده و تست PG واقعی موفق است. بدون CAPTCHA اضافه. | اجرا و تست‌شده؛ اتصال هشدار بیرونی نیازمند میزبان |
| ۷ ـ نوع/حجم/ابعاد/پیکسل، decode محدود و reencode، نام سرور، private/cache/quota | Sharp محدود و WebP، UUID سرور، public/private mapping، مالکیت read، private no-store، quota اتمیک حساب/کل. MIME جعلی، فایل خراب، بیش‌ازحد و quota رقابتی تست شده‌اند. لینک امضاشده ساخته نمی‌شود. | upload جدید اجرا و تست‌شده؛ دادهٔ قدیمی حفظ و استثناها مستند |
| ۸ ـ نقش runtime و migration جدا، رد config ناامن، عدم نشت اسرار و audit | grants محدود و startup role check؛ revoke مستقیم anon/authenticated؛ تست نقش واقعی. config production و Secure cookies تست شده؛ log sentinel و secret/bundle scan انجام شده است. | پیاده‌سازی و اثبات محلی؛ ساخت نقش/secret واقعی وابسته به میزبان |
| ۸ ـ dependency اصلاح‌شده با بررسی مسیر، CI، غیرroot/firewall/DB/backup | pnpm audit/lockfile و exception دقیق تاریخ‌دار؛ Gitleaks؛ workflow push/PR؛ systemd/Nginx/grants؛ راهنمای backup رمزگذاری‌شده و restore. | کد و راهنما آماده؛ CI ابری و backup واقعی اجرا نشده‌اند |
| ۹ ـ regressionهای نام‌برده، typecheck/build، مرورگر و اسکن ایزوله | نتایج فرمان‌های واقعی در `verification.md`؛ PostgreSQL واقعی، S3 loopback و مرورگر؛ `local-scan.json`. ZAP/Java/Docker موجود نبودند و ادعای ZAP نشده است. | انجام‌شده در دامنهٔ محلی؛ هیچ active scan عمومی انجام نشده |
| ۱۰ ـ وضعیت هر یافته، جداسازی اجرا/تست/مستند و منع اعلام پایان با high باز | SEC-001…012 در findings؛ تفکیک صریح در verification. مورد مهم اثبات‌شدهٔ محلی باقیمانده وجود ندارد؛ موارد میزبان نامعلوم، conditional و قابل پذیرش عملیاتی بعدی‌اند. | آمادهٔ تحویل محلی، بدون ادعای استقرار |

گزارش تستِ متوقف‌شده در cleanup به عنوان موفقیت استفاده نشده است. fixture PostgreSQL از پورت آزاد و pg_ctl زمان‌دار برای خاموشی محیط disposable استفاده می‌کند؛ مسیر حذف فقط پس از بررسی محدودهٔ temp پذیرفته می‌شود. اجرای موفق نهایی، جایگزین آن اجرای ناموفق شده است؛ دادهٔ واقعی در این فرایند حذف نشده است.
