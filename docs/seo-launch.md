# راهنمای انتشار، پایش و تصمیم‌های مالک

## نسخهٔ فعال روی VPS

`geo-20261120-r1` در ۲۰ نوامبر ۲۰۲۶ با تأیید مالک منتشر شد. SHA-256 بسته در VPS بررسی شد و آزمون HTTP خارج از VPS هر ۲۵ URL را پوشش داد. سرویس‌های فروشگاه، API، worker و Nginx بعد از انتشار فعال بودند. فایل بازگشت در `/opt/varsa/releases/geo-20261120-r1/backup/rollback.sh` قرار دارد. اولین پیش‌بررسی پیش از تغییر سرویس‌ها به نبود فایل اختیاری source map رسید. اسکریپت انتشار برای همین حالت اصلاح شد و همان بسته فعال شد. [گزارش تغییرات و سنجش GEO](geo-results-2026-11-20.md)

## انتشار SEO قبلی در ۲۰ نوامبر ۲۰۲۶

نسخهٔ `/opt/varsa/releases/seo-20261120-061956` مبنای نسخهٔ بعدی بود. سرویس فروشگاه، API، worker و Nginx فعال بودند. هر ۲۵ نشانی موجود در sitemap زنده بررسی شد. آزمون بیرون از VPS پاسخ ۴۰۴، robots، سیاست noindex مسیرهای خصوصی، TLS و سلامت API را تأیید کرد. افزودن کالا به سبد در Chrome موبایل با مسدودکردن عملیات نوشتن API آزموده شد. وضعیت عمومی ایندکس از نسخهٔ پیشین حفظ شد.

نسخهٔ قبلی تنظیم دامنه و بستهٔ API در زیرپوشهٔ `backup/` همین انتشار قرار دارد. اپراتور مجاز می‌تواند با `bash /opt/varsa/releases/seo-20261120-061956/backup/rollback.sh` پیکربندی و API پیشین را بازگرداند. ثبت sitemap در ابزارهای مالک و سنجش میدانی همچنان در فهرست پایش هستند.

## انتشار و کلید ایندکس

1. همراه lockfile هر دو خروجی مرورگر و SSR را با `pnpm --filter @workspace/varsa-shop run build` بسازید. انتشار شامل `dist/public` به‌عنوان ریشهٔ Nginx و `serve-storefront.mjs`، `package.json`، `dist/server` و وابستگی‌های production بستهٔ فروشگاه است. سرویس، فایل `dist/public/.vite/manifest.json` را در زمان راه‌اندازی می‌خواند. CI و سرور باید از نسخهٔ یکسان فایل‌ها استفاده کنند.
2. اجرای `ops/varsa-storefront.service` و جای‌گذاری نمونهٔ `ops/nginx-varsa.conf` در server block دامنه به مجوز مالک یا اپراتور نیاز دارد. فایل `ops/nginx-security-headers.conf` را هم‌زمان به‌روز کنید. API روی ۵۰۰۰ و کل SSR روی loopback و پورت ۵۱۷۴ می‌مانند. ریدایرکت‌های TLS فعلی HTTP و www به میزبان اصلی را حفظ کنید.
3. در `/etc/varsa/storefront.env` مقدار `SEO_SITE_URL=https://varsasaffron.ir`، `STOREFRONT_API_ORIGIN=http://127.0.0.1:5000` و `SEO_INDEXING=0` بگذارید. `NODE_ENV=production` از unit می‌آید. پیش‌نمایش بیرون از ماشین توسعه را با احراز هویت در لبه یا شبکهٔ خصوصی کنترل کنید.
4. پیش از reload اجرای `nginx -t` را بررسی کنید. با GET و HEAD برای صفحهٔ اصلی، محصول، مقاله، دسته، مسیر اشتباه و فایل تصویر پاسخ، هدر امنیتی و محتوای HTML را بررسی کنید. حساب و پرداخت باید noindex و no-store باشند. آزمون سفارش را با حساب و دادهٔ آزمایشی در staging انجام دهید.
5. پس از تأیید محتوا و فروش، فقط روی میزبان عمومی `SEO_INDEXING=1` را قرار دهید و سرویس SSR را راه‌اندازی مجدد کنید. مقدار HTTPS و Host باید با هم منطبق باشند. robots اکنون sitemap را معرفی می‌کند و head عمومی canonical دارد. یک URL خراب باید ۴۰۴ و مشکل موقت منبع داده ۵۰۳ باشد. در صورت بازگشت موقت به حالت بسته مقدار `SEO_INDEXING=0` را برگردانید. برای rollback کامل، نسخهٔ قبلی فایل‌های release و کانفیگ استقرار را کنار هم بازگردانید.

## حساب‌ها و پایش

- **Google Search Console**. در تصویر ارسالی مالک از ۲۰ نوامبر، پراپرتی `https://varsasaffron.ir/`، نقشهٔ `/sitemap.xml` با وضعیت `Success` و ۲۵ نشانی کشف‌شده را نشان می‌داد. گزارش Pages در حال پردازش بود. پس از خزش مجدد، در URL Inspection نمونه‌ای از هر نوع صفحه را بررسی کنید و گزارش‌های Pages و Performance را بخوانید. [شواهد خط پایه](geo-baseline-2026-11-20.md) · [راهنمای Search Console](https://developers.google.com/search/docs/monitor-debug/search-console-start)
- **Bing Webmaster Tools**. دامنه را با گزینهٔ مالکیت مورد قبول Bing تأیید کنید یا از اتصال Search Console متعلق به مالک استفاده کنید. XML را ثبت کنید و URL Inspection، Site Explorer و گزارش AI Performance در حساب قابل‌دسترسی را بررسی کنید. [Bing Webmaster Tools](https://www.bing.com/webmasters/) · [گزارش AI Performance](https://blogs.bing.com/webmaster/2026/2/Introducing-AI-Performance-in-Bing-Webmaster-Tools-Public-Preview/)
- **GA4 یا ابزار مورد تأیید مالک**. ابتدا شرایط استفاده برای کسب‌وکار و بازدیدکنندگان بازار هدف، متن سیاست حریم خصوصی و سازوکار رضایت و پس‌گرفتن رضایت را بررسی کنید. برای GA4 یک Web Data Stream و Measurement ID واقعی ایجاد کنید. ابزار رضایت می‌تواند با وارد کردن `connectMeasurement` از `src/lib/analytics.ts`، یک تابع `consent` و یک ارسال‌کنندهٔ تأییدشده را متصل کند. این اتصال در کد فعلی غیرفعال است. برای GA4، بارگیری tag را به رضایت محدود کنید و ارسال خودکار pageview و Enhanced Measurement را بررسی و غیرفعال کنید تا مسیر خصوصی و query وارد گزارش نشود. CSP را تنها برای مقاصد مورد نیاز باز کنید و در DebugView ابتدا بدون رضایت و سپس با رضایت آزمون کنید. [Google Consent Mode](https://support.google.com/analytics/answer/10000067) · [رویدادهای Ecommerce در GA4](https://support.google.com/analytics/answer/12924131)
- **تعریف رویدادها**. لایهٔ آماده فقط روی محیط indexable و میزبان اصلی فعال می‌شود. payload مرور صفحه canonical و منبع AI شناخته‌شده در صورت وجود referrer را دارد. مرور محصول، افزودن، شروع سفارش و ثبت درخواست سفارش از مقادیر عمومی کالا با ارز `IRR` استفاده می‌کنند. ثبت درخواست سفارش معادل فروش قطعی نیست. برای گزارش `purchase`، پس از تأیید پرداخت یک رویداد با شناسهٔ تراکنش غیرشخصی و ثبت یکتایی در سامانهٔ مورد تأیید مالک طراحی شود. شماره تماس، نشانی، رسید، کلید پرداخت و URL خصوصی در payload تعریف نشده‌اند.
- **پایش فنی**. وضعیت و زمان پاسخ مسیرهای عمومی، خطاهای ۵۰۳ API و تعداد URLهای sitemap را هفتگی کنار عملکرد جست‌وجو بررسی کنید. پرسش‌ها، URLهای دارای impression، CTR و مسیر سودآور را در سطح صفحه بسنجید. نتیجهٔ آزمایش AI را در همان بازه ثبت کنید. LCP، INP و CLS را پس از فراهم‌شدن دادهٔ میدانی در صدک ۷۵ و به تفکیک دستگاه بررسی کنید. [تعریف و آستانه‌های Core Web Vitals](https://web.dev/articles/vitals)
